STAGE 9 — UNIFIED NORMALIZATION & STANDARDIZATION
---------------------------------------

Create a normalization layer that:

- Accepts outputs from stages 1–8
- Validates, cleans, and standardizes all outputs
- Produces a single **canonical style artifact**

Responsibilities:

A) DTCG Token Normalization
- Validate tokens against W3C DTCG 2025.10
- Enforce:
  • $type
  • $value
  • $description
- Resolve aliases
- Group tokens by category and theme
- Reject invalid or ambiguous tokens

B) Non-DTCG Structure Normalization
- Components
- Layers
- Lighting
- Materials
- Motion
- Semantic style vectors

Each must:
- Conform to a JSON Schema
- Be versioned
- Be extensible

Output:
{
  "styleId": "...",
  "tokens": {...},
  "components": {...},
  "layers": {...},
  "styleSemantics": {...},
  "lighting": {...},
  "materials": {...},
  "motion": {...},
  "lineage": {...}
}

STAGE 10 — BACKEND API & PIPELINE ORCHESTRATION
---------------------------------------

Implement a backend service that:

- Orchestrates the full pipeline asynchronously
- Is deployable to GCP Cloud Run
- Uses job-based execution (not request blocking)

Required endpoints:

POST /ingest/image
POST /ingest/prompt
GET  /styles/:id
GET  /styles/:id/tokens
GET  /styles/:id/components
GET  /styles/:id/layers
GET  /styles/:id/semantics
GET  /styles/:id/depth
GET  /styles/:id/lighting
GET  /styles/:id/motion

Architecture requirements:
- Use a queue (Pub/Sub or equivalent)
- Worker processes handle pipeline stages
- Each stage logs:
  • start time
  • end time
  • errors
  • outputs

Storage:
- Images, masks, depth maps → Cloud Storage
- Structured JSON → Firestore or Postgres
- Embeddings → vector store abstraction (pluggable)
