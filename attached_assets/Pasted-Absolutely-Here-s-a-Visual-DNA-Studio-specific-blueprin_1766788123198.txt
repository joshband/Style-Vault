## Architecture Tailored to Your Repo

### 1. Make Tokens the Only Source of Truth (No Exceptions)

**Rule:**
If it’s not in `style.tokens.json`, it doesn’t exist.

**Concrete changes:**

* Every style has exactly one immutable token file:

  ```
  /styles/{styleId}/tokens.dtcg.json
  ```
* Images are *linked*, not embedded.
* All UI views read from tokens—not derived state.

**Why this matters:**
It prevents “UI drift” and keeps Visual DNA Studio honest.

---

### 2. Token Completeness > Token Accuracy (At This Stage)

Your app should always emit a **full DTCG surface area**, even when confidence is low.

That means:

* Colors, spacing, typography, radii, shadows, opacity, depth, motion
* Composite types populated with inferred defaults
* Confidence metadata stored in `$extensions.visualDNA.confidence`

Example:

```json
{
  "spacing": {
    "md": {
      "value": "12px",
      "$extensions": {
        "visualDNA": { "confidence": 0.63 }
      }
    }
  }
}
```

This allows:

* Honest UI messaging
* Future reprocessing
* Downstream automation

---

### 3. Treat CV as a *Resolver*, Not an Oracle

In Visual DNA Studio:

* CV **suggests**
* Heuristics **stabilize**
* Tokens **decide**

Your current lightweight OpenCV approach is correct. Do *not* introduce ML-heavy models here.

Recommended breakdown:

* **Color:** k-means + perceptual clustering (ColorAide)
* **Spacing:** bounding box deltas → histogram → mode collapse
* **Typography:** size clustering + contrast heuristics
* **Shadows:** edge halos + luminance gradients
* **Depth:** simple monocular heuristic (blur + occlusion)

If a signal is weak—emit it anyway, tagged with low confidence.

---

### 4. Storage: Hybrid, But Opinionated

You already outlined this—and it’s the right call.

**Canonical store:**

* Object storage for images
* Postgres for metadata + token JSON

**Never store:**

* Base64 images
* Derived previews
* Token subsets

**Always serve:**

* Thumb URLs only for grids
* Medium URLs for inspection
* Originals only for reprocessing

**No chips. No tags. No metrics.**

Token inspection belongs in a **secondary, deliberate view**—not the browsing surface.

This reinforces the core idea:

> *Styles are visual artifacts, not datasets.*
